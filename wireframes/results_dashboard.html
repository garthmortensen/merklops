For builders: how these dashboards bind to the Merkle DAG

Dashboards never read the DAG. They read published outputs from a results store, by logical name and schema version, so the DAG can change shape without breaking them.

  1. Publish step (a sink, outside the hash). After a run finishes, a publisher reads the run record and copies each exported output into the results store as tidy rows: run_id, output, schema_version, year, value, kind, plus run facts (date, status, total sha, structure sha). It is append-only and keyed by run id, like the run records.
  2. Exported outputs are a contract. A node marks an output export: true with a schema version. Dashboards bind to steel_projection.prices@v1, never to node internals.
  3. Dashboards are pack artifacts. Each model's dashboard is a spec in the pack, pinned and versioned like code, that names the outputs it needs and the schema versions it supports.
  4. Structure changes are compared, not hidden. When two selected runs have different structure shas, the page diffs their graphs (nodes and edges added or removed) and compares outputs by logical name. An output whose inputs changed is flagged "definition changed".
# dashboards/cost_index.yml (in the pack)
dashboard: cost_index_overview
version: 1.2.0
binds:
  index:  cost_index.index@v1
  prices: "*_projection.prices@v1"      # every model's prices, whatever the DAG holds
compare:
  key: [year]
  flag_definition_change: true           # inputs of cost_index differ between runs
